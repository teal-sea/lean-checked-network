# The phase-grid network adds mod p: a Lean 4 / Mathlib proof

Lean `leanprover/lean4:v4.35.0`, Mathlib tag `v4.35.0` (commit `56a005855ea17e0b0958f73ec801ae140b0a1679`),
oleans from `lake exe cache get`, nothing compiled from source. Written 2026-10-16 (first session), extended the same day (second session: `Close.lean`, `P7Link.lean`).

## The statement

Gromov's analytic two-layer network for addition mod p, with the phases of its neurons fixed on a
grid instead of random: for each frequency k in a list S, eight neurons with phases
phi1 in {0, pi/2, pi, 3pi/2} and phi2 in {0, pi/2}, weights

    E1[a] = cos(2 pi k a / p + phi1),  E2[b] = cos(2 pi k b / p + phi2),  W2[c] = cos(2 pi k c / p + phi1 + phi2),

every weight multiplied by a scale M and rounded to the nearest integer (`round x = floor(x + 1/2)`),
and the answer computed by `LeanCheckedNetwork.answer` from the first repository's `Network.lean`
(copied here verbatim: `PhaseGrid/Network.lean`). With

    g = a gap for S:  for every shift s with 0 < s < p,  sum over k in S of cos(2 pi k s / p)  <=  |S| - g,

the theorem `PhaseGrid.adds_mod_p` says: if 24 |S| < M g then the integer network answers
(a + b) mod p for all a, b < p. `adds_mod_p_of_gap` is the same with g spelled out as |S| minus the
largest wave sum. `adds_mod_p_full` says: for every p >= 3, all frequencies 1 .. floor((p-1)/2) and
every M >= 25, the network adds mod p; for odd p, `adds_mod_p_full_odd` gives it for every M >= 24.

Nothing in the statement needs p prime. p = 1 and p = 2 are excluded only because the frequency
list would be empty (p = 2) or the gap condition vacuous (p = 1); `adds_mod_p` itself needs only
0 < p.

## The argument, in plain words

1. Expanding `W2[c] (E1[a] + E2[b])^2` for one neuron gives nine cosines; eight of them carry a
   phase `alpha phi1 + beta phi2` with `(alpha, beta)` in `{(1,1), (3,1), (1,-1), (1,3), (-1,1), (2,2),
   (2,0), (0,-2)}`. Summing over phi1 in {0, pi/2, pi, 3pi/2} kills every family with alpha not a
   multiple of 4, and summing over phi2 in {0, pi/2} kills `(0,-2)`. What is left is
   `4 cos(2 pi k (a + b - c) / p)` per frequency. In Lean this is one polynomial identity (`octet`).
2. At the right answer every wave is at its peak, so the real score is `4 |S|`; at a wrong answer the
   shift `a + b - c` is not a multiple of p, and the score is at most `4 (|S| - g)`.
3. Rounding: with `w' = round(M w)`, `x = round(M e1) + round(M e2)`, `X = M e1 + M e2`,
   `w' x^2 - M w X^2 = (w' - M w) x^2 + M w (x - X)(x + X)`, and `|w' - M w| <= 1/2`, `|x| <= 2M`,
   `|x - X| <= 1`, `|x + X| <= 4M`, `|M w| <= M` give at most `6 M^2` per neuron, `48 M^2 |S|` per score.
4. So the right answer's integer score exceeds every wrong one by at least
   `4 g M^3 - 96 |S| M^2 = 4 M^2 (M g - 24 |S|) > 0`, and the repo's `argmax` returns it.
