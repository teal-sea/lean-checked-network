# Three more networks, trained and kernel-checked on 2026-10-16

Trained with the repository's `train.py` (learning rate 0.01, weight decay 1.0, 20,000 full-batch
steps, 128 neurons) in a 4-core container, frozen to whole numbers exactly as the repository does,
and checked the repository's way: one `decide +kernel` per row through the fast evaluator,
`lake build`, every generated module replayed with `leanchecker` (two at a time), `#print axioms`.
The machine was shared with other Lean jobs throughout, so the times are upper bounds.

The 30 percent run was already right on every pair at its first checkpoint (step 2,000) and
keeps about a third of the winning margin of the 50 percent runs. All three Lean packages were
generated by `gen_lean.py` with 16 row files, namespaces `P113S1`, `P97S0` and `P113F30`, in a
scratch copy of `lean/` outside the repository; the weights are not committed here.

The first attempt at these checks failed before any kernel work: `gen_lean.py` wrote the source
path into a Lean block comment, and the container's scratch path contained `/-`, which opened a
nested comment that never closed. The fix (only the file name goes into the comment) is in the
same pull request as this directory.
